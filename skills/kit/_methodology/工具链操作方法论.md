# 工具使用方法论与题型路由（本地/托管通用）

## 总体流程：O-H-V-D

1. **Observe（观察）**：读取题面、目标描述、附件、平台给出的网络/进程/凭证/规则；保存原始输入与时间戳。对二进制执行 `file`、`sha256sum`、`checksec`、`readelf -h -S -s`，先静态识别，不猜测答案。
2. **Hypothesize（假设）**：形成最多 3 个可证伪假设；每个假设写明证据、预期观察、低成本验证办法。Web 列入口与参数；二进制列输入点、边界、保护和可达路径。
3. **Validate（验证）**：一次只改变一个变量。优先无副作用探测；保存命令、返回码、stdout/stderr、请求/响应、样本哈希。阴性结果也记账，避免重复试错。
4. **Deliver（交付）**：只提交平台要求格式的 flag / 证据 / 结果；核对平台回执，停止任务进程，清空跨题临时状态。

### 证据账本字段

`时间 | 题目ID | 假设 | 命令/请求 | 输入哈希 | 观察到的输出 | 结论(支持/否定/未定) | 下一步 | 副作用/恢复`

## 工具操作速查

### Ghidra

图形环境：运行 `ghidraRun`；无 GUI 的容器中使用 headless analyzer：
`analyzeHeadless /tmp/ghidra-project ProjectName -import ./sample -postScript MyScript.java`
先确认官方版本的启动脚本与 headless 参数：`/opt/ghidra/support/analyzeHeadless -help`。步骤：新建项目→导入样本→自动分析→看入口/字符串/交叉引用→追踪危险调用→记录伪代码地址和触发条件。脚本批量化之前先在单样本验证。

### JADX（Android/Dex）

`jadx -d out app.apk` 反编译；`jadx-gui app.apk` 图形查看。先看 Manifest、导出组件、权限、网络安全配置，再按 API/字符串交叉引用检查敏感数据流。JADX 输出是近似重建源码，重要结论需回到 smali/字节码或运行行为确认。

### radare2

`r2 -A ./sample` 自动分析；`aaa` 补充分析；`afl` 函数列表；`pdf @ main` 反汇编函数；`iz` 字符串；`axt @ sym.imp.system` 看交叉引用；`q` 退出。先在副本上分析，不对未知目标用写模式。

### angr

Python 骨架：
```python
import angr, claripy
p = angr.Project("./sample", auto_load_libs=False)
state = p.factory.full_init_state(args=["./sample", claripy.BVS("arg", 8*64)])
sim = p.factory.simulation_manager(state)
sim.explore(find=0xTARGET, avoid=0xAVOID)
print(sim.found[0].posix.dumps(0) if sim.found else "no path")
```
把 `TARGET/AVOID` 换成已从反汇编确认的地址；优先符号执行短路径，遇到循环/外部依赖时限制状态爆炸并退回手工约束。结果要在真实样本上重放。

### pwntools

本地：`p = process("./sample")`；远端：`p = remote(HOST, PORT)`；`p.recvuntil(...)` 同步提示；`p.sendline(payload)` 发送；`p.interactive()` 仅在交互调试时使用。先 `checksec`/`ELF('./sample')` 读保护和符号；架构必须匹配；远端地址与本地不可默认相同。先单次最小化验证，再整理确定性脚本。

### JADX/Ghidra/r2 一起用

JADX 先还原 Java 层调用与组件；Ghidra/r2 看 native `.so`；按 JNI 边界连接 Java 参数、native 函数和敏感操作。对每个结论写明文件哈希、函数/地址、调用链、复现实验。

## 可复现与状态管理

- 每题建立单独目录：`task-ID/{input,evidence,notes,output}`；保留原件只读，分析在副本进行。
- 给每个命令设置超时；长时间卡住先记录后终止，不自动无限重试。
- 每个阶段定义停止条件：假设被证伪、平台已确认完成、超出单题时间、工具依赖缺失。
- 本地模式先验证 API 生命周期与调试链路；托管模式再验证入口命令、环境变量名称、超时、资源限制与离线依赖。
- 容器中不要依赖桌面 GUI；需要 headless 或 RPC 的工具须单独测试。
- 仅按公开题面和平台提供的目标进行验证；不要把某一题的凭据、产物或状态带入下一题。
